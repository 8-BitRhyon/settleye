# Local promise gate: fine-tune bench

The question: can a free, local checkpoint replace a hosted calibrated decision
model in front of extraction? The earlier zero-shot tests said no. This bench
tests the remaining path: fine-tune an open checkpoint on labeled promise data.

The recorded model is TinyBERT 4-layer (`huawei-noah/TinyBERT_General_4L_312D`,
120 MB base weights, 55 MB saved checkpoint). The model card does not state a
license. Training runs on Apple Silicon with MPS in about 25 seconds. No API
calls and no model spend.

## What the gate decides

The gate asks one question before the extractor runs:

- `needs_extraction`: did the agent commit to a financial action (binding,
  conditional, superseded, or retracted)?

Policy explanations, status updates, and requests for information are
`info_only` and should be skipped. The modality head still has to tell all five
states apart so the eval can be compared with the earlier model runs.

## Data

`generate_data.py` builds 1,000 training rows, 250 validation rows, and 250 test
rows from 50 scenario families. Labels are constructed by the scenario, not
generated by a model. Train and held-out rows use different phrasings so the
test is not a memorization check.

The 12 committed eval cases are never used for training, calibration, or
threshold selection.

## Recorded result

On the committed 12-case eval, the TinyBERT gate keeps all 10 commitments,
skips the clean status check, and agrees with the extractor's manifest on all 12
cases. The info-only policy case is kept, which is a strict-label false positive
but a safe keep.

On the 250-row held-out set at threshold 0.20: 98.4 percent commitment recall,
98.4 percent non-commitment skip, 88.0 percent modality accuracy. On the 300-row
money-adjacent Bitext sample: 6.3 percent discard at 0.20, 12.7 percent at 0.50.
Zero-shot Laya discarded 2 percent.

Full result and limits: `docs/research/22-free-gate-finetune.md`.
Compact evidence: `results/summary.json`.

## Reproduce

```bash
cd bench/finetune
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python torch transformers pandas pyarrow
.venv/bin/python generate_data.py --out data
.venv/bin/python train_tinybert.py \
  --data data \
  --output out/tinybert_gate \
  --epochs 4 --batch-size 16 --device mps
.venv/bin/python eval_tinybert.py \
  --model out/tinybert_gate \
  --device mps
.venv/bin/python summarize.py \
  --report out/tinybert_eval_report.json \
  --out results/summary.json
```

The recorded environment used `torch` 2.15.0 and `transformers` 5.22.1. Add
`laya==0.4.21` only for the larger 421M path. The first run downloads the
120 MB TinyBERT base weights from Hugging Face.

## The 421M path

`train_gate.py` and `eval_gate.py` fine-tune and score Laya (ModernBERT-large,
421M). They are kept for a larger-memory or CUDA machine. On this 16 GB M4 the
full-encoder run began swapping about 4 GB and was abandoned at 6 percent; a
frozen-head run stalled in its calibration pass. The 55 MB checkpoint is the
recorded run.

## Artifacts

- `generate_data.py`: labeled scenario generator.
- `train_tinybert.py`: TinyBERT fine-tune with the gate and modality heads.
- `eval_tinybert.py`: scores the gate on the eval set, held-out data, and the
  300-row Bitext sample.
- `summarize.py`: compacts the full eval report into `results/summary.json`.
- `train_gate.py`, `eval_gate.py`: the 421M Laya path for larger machines.
- `smoke_rows.jsonl`: 8-row fixture for the larger Laya path.
- `test_metrics.py`: metric math checks.
- `out/`: generated weights and full reports, gitignored.
- `docs/research/22-free-gate-finetune.md`: the measured result and decision.

## Limits

- Training data is synthetic. It covers shapes, not real merchant transcripts.
- The primary eval is 12 cases. The held-out synthetic set is larger but shares
  the generator's author bias.
- One training run. No seed sweep, so variance is unmeasured.
- The Bitext sample is money-adjacent and has no labels for our schema, so its
  discard rate measures cost, not recall.
- The TinyBERT model card does not state a license. Verify it before
  redistributing the checkpoint.
