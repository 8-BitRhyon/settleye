The problem

Promises go out. Money never follows.

The gap between what the agent said and what the ledger shows is where refunds leak.

01

Phantom refunds

The agent says “refund processed.” The ledger says $0.00. The customer waits, then chargebacks.

02

Policy breaches

Full refunds on final-sale items, over-limit amounts, duplicate credits. Found at close, if ever.

03

Silent cancellations

“Cancelled” in chat, still billing in Stripe. The next cycle triggers the dispute.

How it works

Pull each promised dollar, then show the Stripe record or its absence.

01

Extract the promise, not the sentiment

The transcript goes to a pinned Meta open-weight model. The reply must pass a schema or it fails loudly. No regex, no guessing.

{ "action": "refund",
  "amount": 45.0,
  "order_id": "992",
  "terminal_status": "binding" }

02

Join it to settled state

Each binding promise is looked up on the ledger. The diff is the product: dollars promised against dollars moved, per order.

promised  $45.00  #992
settled   $ 0.00
verdict   DRIFT    at risk $45.00

03

Refund the exact shortfall, once

One click retries the shortfall with an idempotent key. A double click returns the original receipt, never a second refund.

refund:992:45.00  -> executed
refund:992:45.00  -> already_executed
ledger unchanged

Objections

Objections, answered

Can't a frontier model just do this?

We ran the comparison rather than argue it. The measurement sits in Proof: same cases, same prompt, and the difference was how each model failed. A model that invents an order number can reconcile against the wrong order. Read the comparison

Why not just switch to a better agent?

Every agent drifts. Air Canada and Priceline proved the premise. Switching agents changes which agent you verify, never whether verification is needed.

Why not vendor guardrails or audit trails?

Guardrails prevent before send for one vendor. Trails log tool calls without checking ledger truth. Settleye verifies after execution, across vendors.

What stops Shopify or Stripe from building it?

They verify their own rails and never read transcripts. Neutrality is the product.

Is the model decorative?

No. The demo shows raw transcript to raw model JSON to diff with no cuts. A wire-level test pins the model ID on every request.
